# v3.1102 端到端功能与互通梳理

## 1. 统一业务主线

| 主线 | 起点 | 核心流转 | 终点/反馈 |
|---|---|---|---|
| 身份与权限 | 微信会话 | `/me` 返回组织、角色、权限范围 | 入口按身份显示，命令仍由后端鉴权 |
| 自下而上业务 | 村/社发起项目 | 提交→审核→请求上级资源→执行 | 完成结果、审计轨迹、消息通知 |
| 自上而下治理 | 上级或基层事项 | 上报→派单→接单→办理→提交验收→验收/退回 | 基层结果可查，上级可督导 |
| 商品与订单 | 商品/购物车 | 结算→按组织分单→待付款→发货→收货→退款 | 订单状态、通知、贡献值确认/冲正 |
| 贡献与权益 | 行为/订单事件 | 申报→审核→可用→抵扣/兑换→退款释放 | 账户、流水、到期与冲正记录 |
| 消息待办 | 各聚合发生事件 | 生成通知→发送→已读 | 白名单内页跳转，无目标则展示详情 |

## 2. 六级治理规范

`GLOBAL(总) → PROVINCE(省/直辖市) → CITY(市/州) → COUNTY(县/区) → TOWNSHIP(乡/镇/街道) → VILLAGE(村/社区)`。

- 数据范围：组织 `path` 是唯一的上下级范围依据，不以前端角色名替代。
- 业务上行：基层拥有业务发起权，上级只审核、协调资源和督办。
- 治理下行：发起组织只能派给合法下级，责任组织接单和办理，发起组织验收。
- 权限分离：`create / assign / handle / verify / audit.read` 分开；前端隐藏无权入口，后端必须再鉴权。
- 并发规范：流转命令使用 `version` 乐观锁，冲突返回 409，页面重拉后再操作。

## 4. 统一界面规范

1. 查询失败：保留旧画面或空态，不注入 Mock 冒充真数据。
2. 命令失败：不更改本地状态，不显示成功，使用后端业务错误文案。
3. 操作成功：重拉服务端状态后再更新页面，支付类以后端订单状态为最终依据。
4. 无权访问：入口隐藏+页面拦截+后端 403 三层保护。
5. 待接能力：统一标注“试点展示/接口未开放”，禁止把本地写入表述为平台已受理。
