# v3.1102 数智治理功能与流程

## 目标

形成“群众和网格自下而上发现问题、六级组织自上而下协助治理”的统一事项闭环。村（社区）是处置与验收的业务落点，乡镇、县区、市州、省和总平台承担跨域协调、督导与资源支持。

## 统一工作台

- 事项入口：群众诉求、网格巡查、民情预警、部门转办统一形成治理事项，避免各模块重复建单。
- 事项台账：按待派单、办理中、待验收、已办结聚合，详情保留来源组织、承办组织、紧急度、时间和版本。
- 协同流程：上报 → 派单 → 接单 → 办理反馈 → 提交验收 → 验收归档；验收不通过退回整改，跨域疑难事项升级协同。
- 关联能力：村务公开、线上议事、平安综治、纠纷调解、便民代办和志愿积分保留原入口，后续以统一事项编号贯通。

## 角色与权限

| 角色 | 主要职责 | 前端授权标识 |
| --- | --- | --- |
| 群众/网格员 | 发现并上报，查看本人或本组织可见进度 | 登录与组织范围 |
| 调度人员 | 判断归口、选择下级承办组织、派单 | `governance.assign` |
| 承办人员 | 接单、反馈进度、提交处置结果 | `governance.handle` |
| 验收人员 | 核验结果、办结或退回整改 | `governance.verify` |
| 上级治理人员 | 范围内查询、督办和跨域协调 | 组织路径数据域 + 对应命令权限 |

前端权限只负责隐藏无效操作，不能代替后端鉴权。每次命令成功后重新查询台账，避免客户端版本覆盖服务端新状态。

### 六级职责

| 层级 | 管理角色 | 核心职责 | 数据范围 |
| --- | --- | --- | --- |
| 总平台 | 总平台管理员；平台负责人、全国调度、安全审计 | 标准制度、全国态势、跨省重大事项、审计规范 | 全国组织树 |
| 省（直辖市） | 省级统筹管理员；省级负责人、督导、跨域协调 | 政策承接、跨市协同、重大事项会商、资源统筹 | 本省全部下级 |
| 市（州） | 市州运营管理员；市州负责人、调度、效能监督 | 跨县协同、运行监测、专业支撑、效能分析 | 本市州全部下级 |
| 县（区） | 县区服务管理员；县区负责人、调度、部门联络 | 县域分拨、部门资源落地、跨乡镇协调、复盘 | 本县区全部下级 |
| 乡（镇、街道） | 乡镇运营管理员；乡镇负责人、调度、验收 | 事项研判、向村社派单、基层力量协调、结果验收 | 本乡镇及下辖村社 |
| 村（社区） | 村社服务管理员；村社负责人、网格、办理 | 民情发现、现场核实、先期处置、过程反馈和回访 | 本村（社区） |

治理原则是“基层主办、上级协办”：上级提供标准、资源、协调和监督，不替代责任组织办理；本级能解决的不升级，确需跨部门、跨区域或重大资源的事项才逐级协调。

## 七步治理流程

1. 发现上报：群众、网格员、村社或预警系统形成唯一事项。
2. 受理研判：发起组织判断归口、紧急度、是否跨域和所需资源。
3. 分级派单：调度员仅向发起组织的合法下级责任组织派单。
4. 接单处置：责任组织接单，持续反馈进度并保存现场证据。
5. 提交验收：责任组织提交完整结果与凭证，进入待验收。
6. 验收回访：发起组织验收；不合格说明原因并退回整改，合格后办结。
7. 归档复盘：保留审计轨迹，重复、超时、跨域或重大事项进入上级复盘。

异常控制：并发版本变化必须刷新后重试；退回必须填写原因；跨域协同、督办、升级、附件、回访和时限规则仍需后端新增命令或查询，不在前端伪造成功。

## 页面降级

- 真实后端启用：只展示接口返回的数据；请求失败不注入演示事项，不改变页面原状态。
- 演示模式：展示代表性事项并允许本地流转，页面和提示持续标注“未提交后台”。
- 组织未绑定：禁止真实上报并提示账号绑定治理组织。
- 无环节权限：展示只读详情和明确说明，不伪造操作成功。

## 后续打通节点

1. 为治理事项补充详情查询、操作轨迹、附件凭证、超时规则和督办命令。
2. 让隐患、调解、代办、议事决议通过统一事项编号创建或关联治理事项。
3. 验收归档后按规则联动治理贡献值，避免仅凭前端点击直接计分。
4. 建立按层级、区域、类型、时效、退回率统计的治理驾驶舱。
