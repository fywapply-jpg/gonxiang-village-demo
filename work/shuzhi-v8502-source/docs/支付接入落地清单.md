## 一、办支付商户号（走资质，找财务/法务）

### 1.1 微信支付（优先，用户主要在微信里）

- **申请入口**：微信支付商户平台 `pay.weixin.qq.com`
- **需要材料**：企业营业执照、法人身份证、企业对公银行账户、已认证的**企业主体**微信小程序
- **申请后拿到**（交给技术团队）：
  - 商户号 `mchid`
  - 小程序 `AppID` + `AppSecret`
  - APIv3 密钥、API 证书（`apiclient_cert.pem` / `apiclient_key.pem`）
- **关键操作**：在商户平台把**小程序 AppID 与商户号做关联绑定**
- **费率**：约 0.6%/笔，无开通费
- **产品**：小程序用 **JSAPI 支付**；网页 H5 用 **H5 支付 / JSAPI**

### 1.2 支付宝

- **申请入口**：蚂蚁开放平台 `open.alipay.com`（+ 支付宝商家中心签约"手机网站支付/小程序支付"）
- **需要材料**：同上（企业资质 + 对公账户）
- **申请后拿到**：应用 `APPID`、**应用私钥**、**支付宝公钥**（RSA2 密钥对）
- **费率**：约 0.6%/笔

### 1.3 数字人民币 / 对公转账（可后置）

- 数字人民币：接入运营机构（工行/建行等）的数字人民币受理，或微信/支付宝内的数币能力
- 对公转账：展示平台/商户对公账户信息，线下转账后人工/银企接口核销

## 二、搭后端（技术团队 · 2 个核心接口）

前端**不能**直接调微信/支付宝下单（密钥不能暴露在前端）。必须有后端中转。

### 2.1 统一下单接口 `POST /api/pay/create`

- **入参**：`{ orderNo, amount(分), method: 'wechat'|'alipay'|'dcep'|'bank', openid?, subject }`
- **后端逻辑**：
  1. 校验订单、金额（以后端订单为准，**不信前端金额**）
  2. 按 method 调对应下单 API：
     - 微信：调「JSAPI 下单」→ 拿 `prepay_id`，按规则生成前端所需的 `timeStamp/nonceStr/package/signType/paySign`
     - 支付宝：调 `alipay.trade.create` / 小程序下单 → 返回 `tradeNo` / `orderInfo`
  3. **务必用直连商户号**：`mch_id` = 收款商户自己的号，货款直达其对公账户
- **返回**：`{ payParams }`（微信的签名参数 / 支付宝的 orderInfo）

### 2.2 支付结果回调 `POST /api/pay/notify`

- 微信/支付宝**异步**通知后端支付结果（不是前端！前端只显示结果页）
- **后端必须做**：
  1. **验签**（用 APIv3 密钥 / 支付宝公钥）——防伪造
  2. **幂等**——同一笔通知可能来多次，处理一次
  3. 改订单状态为"已支付"、记账、触发发货/开票
  4. 按协议返回 `SUCCESS`（微信）/ `success`（支付宝），否则会重复通知

### 2.3 建议补充（非必须）

- `POST /api/pay/query`：主动查单（回调兜底）
- `POST /api/pay/refund`：退款
- 对账：每日下载微信/支付宝对账单核对

## 三、改前端（技术团队 · 只改 1 个文件）

前端**唯一要改**的是 `src/utils/pay.ts` 里的 `requestPay`，把"模拟成功"换成"调后端 + 拉起真收银台"。**收银台页、结果页、下单入口都不用动。**

改造示例：

```ts
// src/utils/pay.ts
export async function requestPay(method: string, order: PayOrder): Promise<PayResult> {
  // 1) 调后端统一下单
  const { data } = await uni.request({
    url: 'https://你的域名/api/pay/create',
    method: 'POST',
    data: { orderNo: order.no, amount: Math.round(order.amount * 100), method /*, openid */ },
  }) as any;
  const p = data.payParams;

  // 2) 拉起对应收银台
  return new Promise((resolve) => {
    if (method === 'wechat') {
      uni.requestPayment({
        provider: 'wxpay',
        timeStamp: p.timeStamp, nonceStr: p.nonceStr, package: p.package,
        signType: p.signType, paySign: p.paySign,
        success: () => resolve({ ok: true, method, tradeNo: order.no }),
        fail: () => resolve({ ok: false, method, tradeNo: '', msg: '支付取消' }),
      });
    } else if (method === 'alipay') {
      uni.requestPayment({
        provider: 'alipay', orderInfo: p.orderInfo,
        success: () => resolve({ ok: true, method, tradeNo: order.no }),
        fail: () => resolve({ ok: false, method, tradeNo: '', msg: '支付取消' }),
      });
    } else {
      // 数币/对公：跳转对应渠道或展示转账信息
      resolve({ ok: true, method, tradeNo: order.no });
    }
  });
}
```

> 注意：前端 `success` 只代表"用户点了支付成功"，**订单真正是否支付成功以后端 `/api/pay/notify` 回调为准**。结果页可先乐观展示，再由后端确认。

### 各端差异（uni-app 一套代码，编译到不同端）

| 端 | 微信支付 | 支付宝 |
|---|---|---|
| 微信小程序 | ✅ JSAPI（需 openid） | ❌（微信内不能用支付宝） |
| 支付宝小程序 | ❌ | ✅ |
| H5（浏览器） | 微信内用 JSAPI，外部用 H5 支付 | 手机网站支付 |
| App | ✅ App 支付 | ✅ App 支付 |

## 五、金融业务的支付（订单贷/保理等）

这类**不是**这里的"收货款"支付，而是**放款/还款**，属**持牌银行/支付机构**的资金业务。平台仅提供数据风控与撮合、跳转持牌机构办理，**不接入商户支付、不碰资金**。参见 `主办银行制` 与 `供应链金融闭环` 页设计。
