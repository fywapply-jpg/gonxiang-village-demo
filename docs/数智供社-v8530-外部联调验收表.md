## 5. 端到端放行条件

使用一笔沙箱订单完整执行：主体审核 → 商品审核 → 订单 → CA 双签 → 托管入金 → 发运 → 物流送达 → 采购验收 → 发票验真 → 财务结算 → 四流三账关账。以下任一项失败，订单必须停留在当前状态并生成审计事件：

1. 任意回调重复发送不得重复写入、重复扣款或重复开票。
2. 金额、数量、购销主体、运单和发票任一不一致时必须阻断结算。
3. 网络超时重试必须使用同一 `Idempotency-Key`，最终只产生一条业务结果。
4. 备份恢复后，组织、商户、订单、合同、支付、物流、发票、验收和审计记录可读取且哈希一致。
