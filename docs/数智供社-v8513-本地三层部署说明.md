# 数智供社 v8513 本地三层部署

系统已拆成三个独立进程，前端页面不直接读取数据库：

| 层级 | 本机地址 | 职责 |
|---|---|---|
| 手机服务前台 | `http://localhost:5173` | 数智供社 v8513 H5、交易与业务演示 |
| 后端管理界面 | `http://localhost:5180` | 交易、商家资质、结算状态、审计日志 |
| API 与数据库 | `http://localhost:8787` | REST `/api/v1`、SQLite 本地持久化 |

## 一键启动

在项目根目录执行：

```bash
npm run dev:local
```

同一 Wi-Fi 下，手机用电脑局域网 IP 替换 `localhost`，例如：

```text
http://192.168.1.20:5173
```

启动脚本会直接显示当前电脑可用的手机前台、管理后台和健康检查地址。电脑防火墙需要允许 Node/npm 接收入站连接。

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY ssh -o ServerAliveInterval=30 -R 80:localhost:5180 serveo.net
```

## 分别启动

```bash
# 1. 后端 API + SQLite
npm run dev:local-api

# 2. 手机服务前台（另开终端）
cd work/shuzhi-v8502-source
npm run dev:h5

# 3. 后端管理界面（另开终端）
cd ../..
npm run dev:local-admin
```

数据库自动创建在 `local-backend/data/shuzhi.db`，首次启动自动写入 v8513 演示订单 `SZGS-2026-850901`。管理端推进订单后，会同时写入履约事件和审计日志。

## 边界说明

- 本地 SQLite 方案用于单机开发、联调和演示，免安装 MySQL。
- `cloud-server/` 中原有的 Fastify + MySQL 服务保持不动，作为独立历史候选服务；它与当前 v8533 前台 legacy BFF 路由和登录响应字段不兼容，完成适配层和全量机构联调前不得直接作为生产后端。
- 当前本地令牌 `local-demo-token` 仅用于开发演示，不能用于公网生产环境。
- 真实支付仍应由银行或持牌支付机构处理；平台数据库只保存业务状态、机构回单号和证据，不沉淀客户资金。
