# 数智供社 v8530 上线执行清单

这份清单用于把 v8530 从本地联调推进到正式环境。未满足“阻断项”的情况下，只能保持演示或灰度，不得对外承诺真实交易。

## 上线前阻断项

1. 为 API、H5 和后台配置已备案的正式域名；证书链、TLS、反向代理和精确 CORS 来源均通过检查。
2. 由微信开放平台完成 `code → session`、账号绑定、令牌轮换、退出失效、冻结与解冻联调。
3. 与银行/持牌支付机构、物流、发票、监管机构分别完成合同、密钥、来源 IP/专线、签名、时间窗、幂等、失败重试和对账验收；四类回调不得共用密钥。
4. 生产环境使用独立随机令牌，禁止把 `SHUZHI_API_TOKEN`、管理员令牌或回调密钥编译进前端；管理员按超级、运营、审核、财务、客服岗位分配。
5. 数据库目录、备份目录和日志目录按最小权限配置；首次启动必须使用空生产库通过就绪探针，确认没有演示主体、商品或订单；至少完成一次备份恢复到临时库并读取组织、商户、订单、审计表。

## 发布顺序

```bash
# 1. 在受限环境文件中填写真实值（不要提交到仓库）
cp deploy/shuzhi-v8530.env.example /etc/shuzhi-v8530.env

# 1a. 只输出字段名和风险，不输出任何密钥值
SHUZHI_ENV_FILE=/etc/shuzhi-v8530.env npm run check:shuzhi-production-env

# 2. 生产变量、HTTPS、身份和机构联调全部通过后再执行
npm run check:shuzhi-production
npm run check:shuzhi-startup
npm run check:shuzhi-backup-restore

# 3. 构建并发布前台、后台和小程序包（正式构建禁止使用局域网地址）
export VITE_API_BASE=https://CHANGE_ME_DOMAIN
cd work/shuzhi-v8502-source && npm run build:h5:production
cd ../.. && npm run build:shuzhi-mp-production
# 管理台正式包不内置管理员令牌；首次打开由管理员输入岗位令牌（仅本会话保存）。
VITE_ADMIN_RUNTIME_MODE=production VITE_ADMIN_API_ORIGIN=https://CHANGE_ME_DOMAIN npm run build:local-admin

# 4. 启动 API（systemd 会先执行生产就绪门禁），随后检查健康状态和关键接口
systemctl enable --now shuzhi-v8530.service
curl -fsS https://CHANGE_ME_DOMAIN/health
curl -fsS https://CHANGE_ME_DOMAIN/health/ready

# 5. 以公网 HTTPS 地址回验当前版本、云服务上下文、机构能力和安全边界
PRODUCTION_API_BASE_URL=https://CHANGE_ME_DOMAIN \
CLOUD_PLATFORM_VERSION=v8533 \
CLOUD_SERVER_DEPLOY_ENV=CHANGE_ME_ENV \
CLOUD_SERVER_SERVICE_NAME=CHANGE_ME_SERVICE \
CLOUD_SERVER_RELEASE_VERSION=v8530 \
PRODUCTION_VERIFY_OUTPUT=docs/releases/数智供社-v8533-生产部署回验证据.json \
npm run verify:production-deployment
```

## 真实交易闸门

交易必须按“主体授权 → 订单 → CA 合同双签 → 托管入金 → 发运/物流回调 → 到货验收 → 发票验真 → 财务结算 → 四流三账关账”顺序推进。任何一步失败、超时或证据不一致，后台保持原状态并进入人工复核；前台不得自行改写为成功。

## 灰度与回滚

- 首批只开放已核验的采购商、供货商和一条支付/物流线路，设置日订单量、金额和风险阈值。
- 每次发布保留版本目录和数据库备份；发现资金、主体或验收状态异常时，先暂停写入和回调消费，再按审计日志定位，不直接删除订单。
- 回滚只切换到上一冻结版本和经验证的数据库备份；恢复后重新执行健康、权限、回调和结算回归。
